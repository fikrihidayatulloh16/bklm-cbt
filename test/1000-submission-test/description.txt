Mendokumentasikan prosedur pengujian adalah langkah wajib seorang Arsitek Sistem. Ini adalah "Buku Pintar" (Playbook) Anda untuk mengulang pengujian beban di masa depan tanpa harus meraba-raba kembali.

Berikut adalah SOP (Standard Operating Procedure) Load Testing BKLM CBT dari awal hingga akhir.

Fase 1: Persiapan Lingkungan (Instalasi Alat)
Anda membutuhkan K6 sebagai mesin penembak (load generator). Karena Anda menggunakan WSL/Ubuntu/Debian Linux, jalankan perintah ini di terminal Anda untuk menginstalnya:

Bash
sudo gpg -k
sudo gpg --no-default-keyring --keyring /usr/share/keyrings/k6-archive-keyring.gpg --keyserver hkp://keyserver.ubuntu.com:80 --recv-keys C5AD17C747E3415A3642D57D77C6C491D6AC1D69
echo "deb [signed-by=/usr/share/keyrings/k6-archive-keyring.gpg] https://dl.k6.io/deb stable main" | sudo tee /etc/apt/sources.list.d/k6.list
sudo apt-get update
sudo apt-get install k6
(Catatan: Anda tidak perlu menginstal Node.js atau Prisma lagi karena K6 berjalan mandiri, dan proyek NestJS Anda sudah memiliki Prisma).

Fase 3: Persiapan Skenario (Skrip K6)
Buat atau cari file bernama load-test.js di folder yang sama (sejajar dengan submissions.json). Ini adalah otak dari pasukan robot Anda yang akan menjawab soal dan menekan finish.

Fase 4: Eksekusi (Membombardir Server)
Pastikan database PostgreSQL dan Redis Anda menyala (via Docker).

Nyalakan server NestJS Anda di terminal pertama:

Bash
npm run start:dev
Buka terminal kedua (di folder proyek), lalu lepaskan tembakan:

Bash
k6 run load-test.js
Fase 5: Membaca Papan Hasil (Metrik Kunci)
Setelah 1 menit, K6 akan berhenti dan menampilkan papan skor. Fokus pada 2 blok ini:

Tingkat Keberhasilan (Checks):

Plaintext
✓ status is 201
✓ finish is 200
Jika ada kegagalan tinggi (checks failed), pastikan Anda melihat pesannya (mungkin waktu ujian habis, atau terblokir Throttler). Kegagalan karena siswa yang sama menekan iterasi berulang saat statusnya sudah FINISHED adalah hal wajar dalam K6.

Kecepatan Respon (HTTP Req Duration):

Plaintext
http_req_duration..............: avg=9.63ms ... max=910.44ms p(95)=28.66ms
Angka rata-rata (avg) harus di bawah 50ms untuk sistem berbasis Redis, membuktikan bahwa API Anda menangani ribuan request secara instan.

Pembersihan: Jangan lupa kembalikan konfigurasi @nestjs/throttler Anda ke nilai normal untuk keamanan rilis produksi Anda.
